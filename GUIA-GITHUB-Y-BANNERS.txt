ARBOLITO — PUBLICAR EN GITHUB PAGES Y AGREGAR BANNERS

1. QUÉ SUBIR

Descomprimí Arbolito-GitHub-Pages.zip. Subí su contenido a la raíz de tu repo
ricardo-3/Arbolito-BR; no subas el ZIP ni una carpeta exterior.
 - index.html: calculadora, cinco cotizaciones y publicidad.
 - scripts/actualizar_pix.py: consulta el HTML público de Compara Pix.
 - .github/workflows/cotizaciones-pages.yml: actualización y publicación.
 - imagenes/: conservá las imágenes que ya tengas en esta carpeta.
 - README.md, esta guía y ACTIVAR-COTIZACIONES.txt.

ATENCIÓN: .github empieza con un punto y puede estar oculta en tu computadora.
Si no se sube al arrastrar, creá el archivo desde GitHub:
Add file > Create new file, nombre .github/workflows/cotizaciones-pages.yml.
Copiá todo el contenido del archivo del ZIP y confirmá en main.
En macOS, Cmd+Shift+. muestra archivos ocultos. En Windows usá Ver > Mostrar
> Elementos ocultos. No reemplaces tus banners existentes por otros.

2. PUBLICAR Y ACTIVAR LA TABLA

1) Abrí https://github.com/ricardo-3/Arbolito-BR
2) Add file > Upload files. Subí los archivos y carpetas a main.
3) Confirmá con Commit changes. Revisá que scripts y .github estén presentes.
4) Settings > Pages > Build and deployment > Source: elegí GitHub Actions.
   Esta versión usa Actions; no dejes "Deploy from a branch".
5) Actions > Arbolito - cotizaciones y Pages > Run workflow > main > Run workflow.
6) Esperá la marca verde en build y deploy.
7) Abrí https://ricardo-3.github.io/Arbolito-BR/ y recargá.

El horario programado consulta aproximadamente cada 15 minutos. GitHub puede
retrasar ejecuciones, así que no es tiempo real ni un intervalo garantizado.
Los pushes a main también vuelven a publicar. Si GitHub desactiva la ejecución
programada por inactividad, entrá a Actions y volvé a habilitar el workflow.

Si Compara Pix no responde o cambia su tabla, la consulta falla y no se publica
una nueva versión. La última web publicada se mantiene disponible. Después de
una hora la tabla avisa "Consulta antigua". La calculadora sigue funcionando
con el valor que ingresa cada usuario. Revisá el error en Actions.

No requiere PHP, claves ni un servicio de cotizaciones de pago. La lectura se
hace en GitHub Actions y los visitantes reciben HTML estático de tu Pages.

3. TAMAÑO Y DISEÑO DEL BANNER

Tamaño recomendado: 1200 x 400 píxeles.
Proporción: 3:1, horizontal. También sirve 900 x 300 píxeles.
Formato: JPG para fotos, PNG para gráficos o WebP para un archivo más liviano.
Peso recomendado: hasta 200 KB por imagen, para que cargue rápido en el celular.

Diseñá el anuncio completo en la imagen: logo, texto, foto y llamada a la acción.
Al agregar una imagen, la app oculta el título, la leyenda y el número del banner
de ejemplo, para que no se superpongan con tu diseño. Las flechas y los puntos
siguen funcionando. Si configurás un enlace, toda la imagen será clickeable.

En un celular base se verá aproximadamente de 353 x 118 píxeles. En uno más
grande crece manteniendo la proporción. Usá texto grande y breve: como guía,
un título de 60 px o más en el diseño de 1200 px. Probalo en el celular.
Dejá unos 50-60 px de margen dentro de la imagen y evitá textos largos.
Si usás otro formato, la imagen puede recortarse para ocupar el espacio 3:1.

4. SUBIR LA IMAGEN AL REPOSITORIO

1) Exportá el primer anuncio como banner-1.jpg.
   Si elegís PNG o WebP, usá banner-1.png o banner-1.webp.
2) Abrí la carpeta imagenes en tu repositorio de GitHub.
3) Elegí Add file > Upload files y arrastrá la imagen.
4) Confirmá el cambio en la rama que publicás (normalmente main).
5) Verificá que la ruta sea imagenes/banner-1.jpg.

Usá nombres en minúsculas, sin espacios ni tildes. La extensión debe coincidir
exactamente con la del archivo. "banner-1.JPG" y "banner-1.jpg" no son la misma
ruta. No basta con renombrar la extensión: exportá en el formato elegido.

5. CONECTAR LA IMAGEN AL PRIMER BANNER

1) Volvé a la raíz del repositorio y abrí index.html.
2) Tocá el lápiz para editar el archivo.
3) Buscá "BANNERS DEL CARRUSEL" (Ctrl+F, o Cmd+F en Mac).
4) Debajo vas a ver "const banners = [" (puede aparecer sin espacios).
   Hay tres elementos, uno por cada anuncio.
5) Reemplazá SOLAMENTE el primer elemento por este ejemplo:

  {title:'Marca de mi amiga',note:'',image:'imagenes/banner-1.jpg',imageAlt:'Anuncio de Marca de mi amiga',href:''},

6) Reemplazá Marca de mi amiga por el nombre real. En imageAlt escribí una
   descripción breve de lo que ofrece el anuncio, para quien usa lector de pantalla.
7) Si el archivo es WebP o PNG, cambiá la extensión de image también.
8) Para que se abra un destino al tocar la imagen, completá href con el enlace
   completo de tu amiga. Por ejemplo: href:'https://ejemplo.com'.
   Reemplazá ese enlace por el verdadero. También podés usar un enlace de
   Instagram o WhatsApp. Si no querés enlace, dejá href:''.
9) Conservá las comillas, las llaves y la coma final. Para texto con apóstrofes,
   usá comillas dobles en ese valor: title:"La tienda de Ana".
10) Tocá Commit changes y confirmá en la rama publicada.
11) Esperá a que termine la actualización de Pages y abrí la app en el celular.

No pongas una barra al comienzo de image. Usá 'imagenes/banner-1.jpg',
no '/imagenes/banner-1.jpg': así funciona dentro de la dirección /arbolito/.
No uses el enlace de la página de GitHub donde se ve el archivo.

6. SEGUNDO Y TERCER BANNER

Repetí los mismos pasos para los otros dos elementos de const banners.
Usá imagenes/banner-2.jpg e imagenes/banner-3.jpg, con sus propios títulos,
descripciones y enlaces. El carrusel mantiene tres posiciones.
Si dejás image:'', esa posición conserva el diseño tipográfico de ejemplo.
Si una imagen no carga, vuelve a mostrarse el título y la nota de esa posición.

7. CAMBIAR UNA IMAGEN DESPUÉS

Podés reemplazar el archivo con el mismo nombre, sin editar index.html.
Si el navegador sigue mostrando la anterior, recargá o abrí una pestaña privada.
Para evitar una imagen vieja en caché, subí banner-1-v2.jpg y actualizá image
con esa nueva ruta. No se requieren cambios en los cálculos.

8. COMPROBAR QUE TODO FUNCIONE

 - Al abrir, los dos campos muestran 0 y el total 0.
 - En pesos: cotización 316 y costo 1000 dan ARS 316.000 al tocar Calcular.
 - Tocá una de las cinco filas: se carga su precio y el total vuelve a 0.
 - Ver cotizaciones en Compara Pix abre https://comparapix.ar/ en otra pestaña.
 - Las flechas, los puntos y el deslizamiento recorren los tres anuncios.
 - Tu imagen se ve sin títulos de ejemplo encima.
 - Si agregaste href, tocar el anuncio abre el destino en una pestaña nueva.

Si aparece un error 404, verificá que index.html esté en la raíz y que Pages
esté configurado con la rama correcta y /(root).
Si la imagen no aparece, comprobá ruta, extensión, mayúsculas y que hayas
confirmado ambos cambios: subir la imagen y editar index.html.

9. CÓMO FUNCIONA

La calculadora no usa APIs ni guarda los importes que ingresa la persona.
La tabla consulta el HTML público de https://comparapix.ar/ desde GitHub Actions;
no incrusta ni copia la web completa. Extrae los primeros cinco precios en ARS
por BRL, mantiene su orden y cita a Compara Pix con enlace.
"Consultado" es la hora de lectura de la página, no la hora de actualización
de las billeteras. El navegador muestra esa hora en la zona del visitante.
Las ofertas, comisiones y cashback no se incorporan al cálculo: confirmá el
importe final en tu billetera. Al tocar una fila se copia su precio al campo,
se borra el resultado anterior y tenés que tocar Calcular.

Hay consultas de red y ejecuciones programadas. No se usa una API de pago ni
un proxy externo. Los runners estándar de Actions son gratuitos en repositorios
públicos según GitHub. Mantener el repo público es parte de esta configuración.

Compara Pix bloquea iframes de GitHub Pages con frame-ancestors. Para una ventana
en vivo tendrían que habilitar tu dominio o proporcionar un widget oficial.
